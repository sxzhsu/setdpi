Why images default to 72 DPI

72 is not a print density. It is a leftover screen convention from the original Macintosh, whose 72 pixels per inch matched the PostScript point so that 12-point type was 12 pixels tall. Browsers, Save for Web, most screenshot tools, Photoshop’s New dialog, and every major AI image generator still write 72 — or omit the tag, which many readers treat as 72. Screens never consult it. A 1920 × 1080 screenshot looks identical on a monitor whether it is tagged 72, 96, or 300.

That is why the file you just downloaded “says 72 DPI” even though you never chose 72. Three sources dump 72 files into print jobs every day:

Browsers and the web. Right-click Save Image, a screenshot of a landing page, a PNG exported from Canva or Figma for the web — the density field is 72 or blank. The picture looks sharp on a Retina display because the display is counting pixels, not inches. A print RIP does the opposite: it reads 72 and stretches those pixels across a claimed poster.

Photoshop and “new document” defaults. File → New still offers 72 PPI for screen/web presets. Save for Web and many “export for screens” paths strip or rewrite density to 72 even when the working file was 300. A designer who built an 8.5 × 11 in layout at 300, then exported a flattened JPEG for the printer, often hands over a 72-tagged file with the original pixels intact.

AI image tools. ChatGPT, Midjourney, DALL-E, Stable Diffusion, and Gemini all save at 72 DPI. Pixel counts are usually generous — ChatGPT 1024 × 1024 or larger, Midjourney up to 2048 × 2048 — but the tag tells a printer those pixels occupy 14+ inches. Preflight that wants 300 will bounce them. The honest fix is a tag rewrite, not a resample, unless you actually need more pixels than the model produced.

The print shop’s preflight does not know or care about that history. It sees 72 and rejects. If you are not sure what the file currently claims, check it on the DPI Checker first.

What actually changes when you convert 72 to 300

Only the density tag. Pixel width and height stay exactly the same. File size stays essentially identical. Quality is identical because the decoder never runs.

What does change is the claimed print size. Print inches = pixels ÷ DPI. Going from 72 to 300 shrinks the claimed inches by a factor of 300 ÷ 72 ≈ 4.17. A 1200 × 1800 px web image tagged 72 claims 16.7 × 25 in — a poster the pixels cannot support. Tagged 300, the same pixels claim 4 × 6 in, which is a real photo-lab size. That is the entire conversion.

Those two operations — tag rewrite and resample — are constantly sold as the same thing. They are not.

Metadata rewrite (this tool): the JPEG or PNG keeps every pixel sample. Only the density instruction changes. Print size shrinks because the same pixels are asked to sit closer together. A 4.2 MB file is still a 4.2 MB file.

Resampling (Photoshop Image Size with Resample on, most “enhance” websites): the software creates a new pixel grid. Going from 72 to 300 “the resample way” on a 72 DPI 4 × 6 in image tries to manufacture about 4× the pixels on each side. That is a new picture. It can look acceptable or it can look smeared; either way it is lossy, and for JPEG it is a second generation of compression on top.

Use the rewrite when the pixels already cover the print. Use a resample or an AI enlarger only when they do not. If they do not, no DPI converter will save the job — including this one. SetDPI does not upscale. For the vocabulary gap between DPI and PPI, read DPI vs PPI. The lossless changer also lives on the homepage.

Check before you convert

Pixels decide the maximum print. The 72 tag does not. Before you send a screenshot or an AI download to a lab, divide each side by 300. If the inches you get are at least the inches you will print, rewrite 72 → 300 and stop. If they are not, you need a larger original.

Frequently asked questions

Why is my image 72 DPI?
Browsers, Photoshop's New dialog, Save for Web, screenshot tools, and AI generators (ChatGPT, Midjourney, DALL-E, Stable Diffusion, Gemini) still default to 72 DPI. That number is a leftover from the original Macintosh, whose 72 pixels per inch matched the PostScript point. Screens never consult it, so the picture looks fine on a monitor. The file still says 72, and that is what a print shop's preflight reads.
Can I convert 72 DPI to 300 DPI without losing quality?
Yes — if you rewrite the density tag instead of resampling the pixels. This tool changes JFIF/EXIF (JPEG) or pHYs (PNG) in your browser. Is 300 DPI the same as 72 pixels?
No. DPI is a density label, not a pixel count. A 1200 × 1800 px file is 1200 × 1800 px whether it is tagged 72 or 300. At 72 DPI those pixels claim about 16.7 × 25 in; at 300 DPI they claim 4 × 6 in. The pixels do not grow or shrink. Only the claimed print size changes.

Will my 72 DPI photo look blurry when printed at 300 DPI?
It depends on the pixel count, not on the old 72 tag. Print inches = pixels ÷ 300. A 1200 × 1800 px file tagged 72 is a sharp 4 × 6 in print at 300. A 400 × 600 px screenshot becomes 1.3 × 2 in at 300 — fine as a thumbnail, blurry if you stretch it to a full page. Changing 72 to 300 does not invent pixels.
How do I know if my 72 DPI image has enough pixels for 300 DPI printing?
Divide each side in pixels by 300. That is the largest sharp print in inches. 1200 × 1800 px → 4 × 6 in; 2400 × 3000 px → 8 × 10 in; 2550 × 3300 px → US Letter; 3000 × 4500 px → 10 × 15 in. The tool shows this for every file you drop. If the inches are smaller than the paper you ordered, you need a larger original, not a higher tag.
Why do print shops reject 72 DPI files?
Preflight software reads the density integer in a second. A file tagged 72 is flagged as screen-resolution even when it has enough pixels for the order. A 2400 × 3000 px photo tagged 72 claims a 33-inch poster; against an 8 × 10 job the RIP calls it low-res. The same pixels tagged 300 claim exactly 8 × 10. That bounce is what this page is built for.
